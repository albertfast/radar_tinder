### Düzeltme 1: `silenceAllAudioNow` — Ses durdur, ama bildirimi dismiss etme (Sebep #1)

**Dosya:** `src/services/NotificationService.ts` (satır 212-226)

**Sorun:** Fonksiyon hem voice'u durduruyor hem de `cancelAllScheduledNotificationsAsync()` + `dismissAllNotificationsAsync()` çağırarak **gösterilmiş radar bildirimlerini de kapatıyor**. Referans radarbot'ta bu fonksiyon hiç yok.

**Çözüm:** Fonksiyonu ikiye ayır — ses/haptic durdurmaya odakla, bildirim dismiss'i kaldır. Sadece "sesli uyarı" durdurulsun, sistem bildirimleri (banner) korunsun.

```ts
static async silenceAllAudioNow(): Promise<void> {
  // Sadece sesli/voice uyarıyı durdur. Sistem bildirimlerini dismiss ETME
  // çünkü radar uyarısı zaten gönderildi ve kullanıcı görmeli.
  try {
    await VoiceGuidanceService.stop();
  } catch {}
  // NOT: cancelAllScheduledNotificationsAsync ve dismissAllNotificationsAsync
  // kaldırıldı — bunlar aktif radar bildirimlerini öldürüyordu.
}
```

**Etkilenen çağrı yerleri (8 yer — hepsi güvenli, çünkü artık sadece ses duruyor):**
- `App.tsx:289`, `useActiveRadarAlertFeedback.ts:90`, `useRadarDataSync.ts:395`, `useVoiceMode.ts:40`, `RadarSettingsScreen.tsx:132,140,160`

Bu çağrı yerlerinin davranışı iyileşiyor: eskiden ayar değiştirince/senkronizasyonda bildirimler kayboluyordu, artık sadece ses kesiliyor.

### Düzeltme 2: GPS accuracy filtresini gevşet (Sebep #2)

**Dosya:** `src/services/BackgroundService.ts` (satır 29-30)

**Sorun:** Eşikler radarbot'tan çok daha katı:
- `MAX_RUNTIME_LOCATION_ACCURACY_METERS = 260` (radarbot: **1500**)
- `MAX_STARTUP_LOCATION_ACCURACY_METERS = 180` (radarbot: doğrudan `BestForNavigation` kullanır, sabit yok)

**Çözüm:** radarbot seviyesine yaklaştır — runtime'ı `1500`, startup'ı `900` yap. Bu, zayıf GPS/simülatör konum güncellemelerinin radar tespitine ulaşmasını sağlar.

```ts
const MAX_STARTUP_LOCATION_ACCURACY_METERS = 900;   // eskiden 180
const MAX_RUNTIME_LOCATION_ACCURACY_METERS = 1500;   // eskiden 260
```

Not: Bu değişiklik **sadece accuracy eşiğini** gevşetir, GPS jump/tiny-movement filtrelerini (satır 594-632) korur — yani sahte/jitter konumlar hâlâ elenir, sadece düşük ama geçerli doğruluktakiler kabul edilir.

### Düzeltme 3: `onForeground` pending bildirimleri iptal etmesini sınırla (Sebep #3)

**Dosya:** `src/services/BackgroundService.ts` (satır 132-140)

**Sorun:** App ön plana her geldiğinde `cancelAllNotifications()` çağrılıyor. İzin diyaloğu/klavye gibi geçici "active" geçişlerinde bile radar bildirimleri temizleniyor. radarbot'ta da var ama Düzeltme 1'siz olduğu için radar_tinder'da daha zararlı.

**Çözüm:** `cancelAllNotifications` yerine **sadece bilgi/amacı olan pending'leri** (location reminder gibi) temizle, radar_alert'leri koru. En basit güvenli yaklaşım: badge'i sıfırla ama bildirimleri iptal etme. Radarbot'ta `trigger: null` ile anlık gösterilen bildirimler zaten iptal edilemez, bu yüzden bu satır büyük ölçüde gereksiz.

```ts
private static async onForeground(): Promise<void> {
  try {
    await this.startLocationTracking();
    // cancelAllNotifications() kaldırıldı — aktif radar uyarılarını öldürüyordu.
    // Sadece badge'i temizle, bildirimleri koru.
    await NotificationService.setBadgeCount(0);
  } catch (error) {
    console.error('Error in foreground handler:', error);
  }
}
```
